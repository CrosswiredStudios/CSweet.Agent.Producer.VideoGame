# 6.4.2

Fixes the project-proposal stall seen at Qwen Games on 2026-11-09, where the platform rejected the proposal with "The authority envelope must include every active profile staffing role: game-producer." and every retry replayed the same rejected command.

- Staffing authority is no longer a model decision. The prompt no longer asks the model to narrow `authorizedStaffingRoleKeys`, any value the model returns is ignored, and the submitted proposal always carries the Director-approved template envelope.
- Drafts and frozen commands cached by earlier releases have the template authority restored before dispatch, so a stalled collaboration recovers on its next turn without regenerating or changing its idempotency key.
- The model returns only a key and a name for each milestone. Lifecycle stage, target date, evidence types and reviewers are merged from the template in code and can no longer fail validation.
- A platform `ValidationFailed` response is returned to the model once as `evidence.platformRejection` for a single corrective proposal, prepared and frozen under separate keys with the same idempotency key. A second rejection is a terminal blocker that quotes the platform message.

No new permissions are requested. Compatible with SDK 5.14.0 and Contracts 5.3.0; no platform change is required.

Validation: not yet run. The changes were written without a .NET SDK available; run `dotnet test` and the published output's `--self-test` before publishing this release.
