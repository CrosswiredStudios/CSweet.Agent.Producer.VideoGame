# 6.6.4

Moves to `CSweet.Agent.SDK` 5.23.0 (was 5.21.1). No agent code changed. No manifest, capability, grant or configuration
change.

Fixes a stall between sprints seen at QFN Games on 2026-11-12. Sprint 1 completed, but its increment acceptance was
blocked by a "runnable test package" finding that none of the sprint's tasks covered. Producer 6.6.3 asked its model
which task should fix it about every 45 seconds: the model answered "needs planning" each time, its wording differed,
so each saved wait looked new and woke the Producer again. Sprint 2 was never populated.

With SDK 5.23.0 the Producer's delivery-correction step:

- re-runs acceptance instead of planning a repair when the only finding is "no runnable test package" and every Code
  task in the increment declared no browser evidence (needs the matching C-Sweet AgentHost);
- decides a selection once per situation, keyed on the correction, its findings and the exact source revisions,
  never on model wording;
- asks the owner which task's owner should fix a finding no completed task's scope covers, or whether to keep the
  increment waiting, and applies the choice on the next review. It does not ask the model again for the same situation.

Also included from SDK 5.22.0 and 5.22.1: results the platform saved are never retried, and progress can no longer
stop work.

Tests: 526/526 pass against SDK 5.23.0.
