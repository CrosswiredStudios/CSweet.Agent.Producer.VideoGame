# 2.18.3

- Fixes the 2.18.2 access-refusal handling in the live runtime. The MCP runtime reports a broker refusal as an `Unavailable` capability error whose payload is `{"code":"Denied",...}`, so 2.18.2 didn't recognize it and the delivery-recovery commitment still crashed. The Producer now treats that payload, a `*.denied` failure code, or a `Denied` error code as a refusal. It keeps the commitment waiting, escalates once, and accepts `Retry staffing: <what changed>`.
