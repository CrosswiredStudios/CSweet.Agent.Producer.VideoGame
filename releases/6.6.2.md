# 6.6.2

Three model replies are now read with `AgentModelJson.ReadAsync` (SDK 5.21.1). Each derives what follows from the
model's own judgment and sends anything code cannot settle back to the same model call with the exact problem (up to
two corrections), instead of failing the turn with a generic message and starting over on the next attention review.

- **Delivery acceptance** (`NormalizeAcceptance`). Criteria lightly reworded by the model (case, spacing, list
  markers, a final period) are mapped to the exact supplied text. An unsatisfied criterion or a role conflict
  outweighs an "approved" label, and a rejection without findings gets one per unsatisfied criterion. Still sent
  back: missing, invented or repeated criteria, missing evidence, approval with findings, a rejection with nothing
  unsatisfied and no findings, and role-repair criteria that are unknown, satisfied, or set without
  `requiresRoleReplanning`. A ticket that still cannot be reviewed shows the exact problem in its "Producer
  acceptance is waiting" comment.
- **Production brief** (`NormalizeProducerReview`). Open questions outweigh a "ready" label. Still sent back: more
  than 12 questions, no rationale, missing brief headings (named), a brief over 48,000 characters, and "not ready"
  with no question.
- **Scope amendment** (`NormalizeScopeAmendment`). Each replacement is checked against the board before anything is
  saved, with the item and field named: unknown item, finished work, unknown field, an original that is not exactly
  one current entry, an unchanged or existing replacement, repeats. The existing amendment checks still guard the
  saved request.

SDK 5.16.0 to 5.21.1 for package builds (local builds already use the sibling checkout). `ModelJson` and
`PitchProtocol.ParseProducerReview` are no longer used by these paths and remain only for their tests.

Validation: not yet run. Run `dotnet test` and the published output's `--self-test` before publishing. Publish SDK
5.21.1 first.
